## About the Course

The course starts with the fundamentals of Agentic AI: how agents differ from traditional AI models, and the key components of an agent (memory, tools, decision-making). It then moves to **LangGraph**, for designing agent workflows as graphs with state and events, and combines it with **LangChain** to build production-ready agent applications.

**What the course covers**

- Core concepts behind Agentic AI and how intelligent agents operate.
- Building agent systems with LangGraph and LangChain: workflows, state, memory, and event-driven behaviour.
- Single agents with memory and tool use.
- Multi-agent systems with message passing and shared goals.
- Deploying and optimising single-agent and multi-agent applications.

**Projects the course builds toward**

- Autonomous research assistants
- Task automation bots
- Retrieval-augmented generation (RAG) agents
- Knowledge retrieval assistants

**Prerequisites:** basic Python, a basic understanding of APIs and REST services, and familiarity with LLM concepts (OpenAI, Hugging Face models).

## Getting Started

### Prerequisites

- Python **3.14** (see [.python-version](.python-version))
- [uv](https://docs.astral.sh/uv/) (recommended) or `pip`
- API keys for the services used in the notebooks (see [Configuration](#configuration))

### Installation

```bash
# 1. Clone the repository
git clone <repository-url>
cd AgenticAI_Bootcamp

# 2. Create and activate a virtual environment
uv venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 3. Install dependencies
uv pip install -r requirements.txt
# or: pip install -r requirements.txt
```

### Running the notebooks

Open the project in VS Code or JupyterLab, select the `.venv` interpreter as the kernel, and run the notebooks in the order listed below.

```bash
uv pip install jupyterlab   # only if you use JupyterLab
jupyter lab
```

## Configuration

Create a `.env` file in the project root. It is git-ignored, so keys are never committed.

```dotenv
OPENAI_API_KEY=your-openai-key
HF_KEY=your-huggingface-token
PINECONE_API_KEY=your-pinecone-key
PINECONE_CLOUD=aws
PINECONE_REGION=us-east-1
```

| Variable | Used for |
|----------|----------|
| `OPENAI_API_KEY` | OpenAI embeddings and chat models |
| `HF_KEY` | Hugging Face model downloads (exported as `HF_TOKEN`) |
| `PINECONE_API_KEY`, `PINECONE_CLOUD`, `PINECONE_REGION` | Pinecone serverless index |

Later modules will need more keys, such as LangSmith for tracing and a search tool provider. They will be documented here when those modules are added.

## Module 1 — LangChain Foundations

The building blocks of RAG and agent applications: getting data in, turning it into vectors, and retrieving it.

### 1. Data ingestion — [01_Data_ingestion](LangChain-Tutorial/01_Langchain/01_Data_ingestion)

| Notebook | Topic |
|----------|-------|
| `1_data_ingestion.ipynb` | Document loaders for text, PDF, web pages, XML, and Wikipedia |
| `2_text_spilitter.ipynb` | Character and recursive text splitting |
| `3_html_header_text_splitter.ipynb` | Structure-aware splitting of HTML by headers |
| `4_recursive_json_splitter.ipynb` | Splitting nested JSON payloads |

### 2. Embeddings — [02_Embeddings](LangChain-Tutorial/01_Langchain/02_Embeddings)

| Notebook | Topic |
|----------|-------|
| `1_openai_embedding.ipynb` | Hosted embeddings with OpenAI |
| `2_huggingface_embeddings.ipynb` | Local, open-source embeddings with Hugging Face and sentence-transformers |

### 3. Vector databases and retrieval — [03_Vector_database](LangChain-Tutorial/01_Langchain/03_Vector_database)

| Notebook | Topic |
|----------|-------|
| `01_Chroma_db.ipynb` | Persistent local vector store with Chroma |
| `02_FAISS_db.ipynb` | In-process similarity search with FAISS, including distance strategies and saving/loading indexes |
| `03_Pinecone_db.ipynb` | Managed cloud vector store with Pinecone, plus a custom retriever |

The vector database notebooks also cover hybrid search with BM25 and an ensemble retriever, and reranking with a cross-encoder.

## Notes

- **Security:** FAISS `load_local` needs `allow_dangerous_deserialization=True` because it unpickles the index. Only load indexes you created yourself.
- **Cost:** OpenAI and Pinecone calls may incur charges. Check your usage limits before running the notebooks end to end.
- **Reproducibility:** vector indexes are not committed. Re-run the ingestion and vector database notebooks to regenerate them.
